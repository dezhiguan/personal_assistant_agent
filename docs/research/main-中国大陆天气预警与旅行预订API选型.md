## 0. 证据与范围

此次按“大陆供应商提供、覆盖大陆出行场景”筛选，不把中文网站等同于数据或请求全部在境内处理。境内部署连通性、合同主体、数据处理区域及账号实际权限仍需验证。官方公开说明证明能力存在，不证明当前项目已获得调用权。

区分四种能力：航班时刻/动态、可售报价、创建订单、支付后出票/酒店确认与售后。仅有前两项不能标成已预订；订单号也不能证明已付款或履约。本文的建议标为【分析】。

近期资产包括途牛、飞猪的官方 Agent 接口与客户端，以及艺龙 2026 年更新的流程文档。心知 V3 文档和艺龙 2023 年 FAQ 仅作为历史接口/反证线索，不据此承诺当前准入政策；现行服务文档即使早于检索窗口，仍为接口契约依据。

## 1. 需求分析与成功条件

| 任务 | 可观察成功条件 | 所需能力及边界 |
| --- | --- | --- |
| 查询天气预警 | 正确地点、发布机构、时间、等级及原文；区分无预警与调用失败 | 地点解析、预警查询；持续推送另需调度和通知 |
| 查询机票/酒店 | 对应日期和人数的候选、报价、税费及退改规则 | 可售库存/价格接口；地图酒店 POI 不等于房态 |
| 用户确认后预订 | 核验报价和人员，创建可核对订单，明确下一步付款 | 服务端旅客档案、确认门禁、防重复、供应商订单号 |
| 支付与售后 | 支付后出票/酒店确认可核对，取消与退款有状态反馈 | 订单查询/回调、取消/退改、异常核单；不能从创单推断 |

【分析】对目前的单用户个人助理，首选保留和风天气，优先验证途牛的机酒查询/创单能力；以飞猪的查询加跳转作为备选。需要完整交易与售后时，再考察去哪儿机票、艺龙/美团酒店分销。最大未知是账户准入、额度费用及支付后状态获取。

## 2. 产品与技术路线论证

| 路线/供应商 | 官方证据支持的能力 | 门槛、局限及判断 |
| --- | --- | --- |
| 和风天气 QWeather | 中国在预警覆盖清单内；按经纬度查询官方预警；支持个人开发者。[1][2][3] | 当前项目已经接入。天气和基础服务分组每月累计前 50,000 次免费，预警包含在该分组；不是每接口各有额度。[4] |
| 彩云天气 | V2.6 天气响应可附带预警；官方说明预警是增值服务，免费赠送额度不适用，并建议新接入考察 V3。[5] | 备选。V2 在大陆使用 GCJ-02，存在行政区边界匹配限制；不能直接沿用当前 WGS84 地名解析结果。 |
| 聚合数据 | 极端天气预警 REST API，输入经纬度和 Key，返回灾种、等级、发布机构、时间等。[6] | 可作为按量 API 备选；具体套餐、实名/场景审核要求应以账号开通页面确认，本文未确认报价。 |
| 途牛 MCP/CLI | 国内机票有搜索、舱位、预订信息、创单及未支付取消；创单返回 orderId/payUrl，用户打开链接付款。[7] 官方客户端另列酒店搜索、详情、创单工具。[8] | 最值得先验证的 Agent 交易路线。个人账号实际授权、费用/限额未验证；酒店单品文档抓取失败，不能推定支付字段。公开国内机票页未列支付后出票/退款工具。 |
| 飞猪 FlyAI | 官方公开机票/酒店搜索，结果带 jumpUrl/detailUrl；FAQ 说明部分价格要到详情页查看。[9][10][11] | 适合查询和跳转预订。当前已读工具清单不能证明可由 Agent 直接提交订单；“可预订商品”不等于有创单 API。 |
| 艺龙/同程酒店开放平台 | 官方 2026-01-08 流程覆盖房态房价、核价、创单、支付、订单状态和取消。[12] | 酒店完整交易候选；需要商务确认准入和结算。不要把旧 hotel.list 当现行接口。2023 年官方 FAQ 仅说明酒店接入，不应用其证明机票 API。[13] |
| 美团酒店门票分销平台 | 官网明确国内/境外酒店 API 和完整住宿预订流程，也提供 H5、App/小程序唤起。[14] | 合作申请→商务对接→方案确认→开发测试→上线。个人准入、押金/最低量和固定费用未公开确认。应选分销入口，区别于酒店供应商直连。 |
| 去哪儿机票开放平台 | 官方国内商旅 API 说明列搜索、预订、生单、支付、订单查询、退票和改签。[15] | 多航司完整交易候选；注册签协议后可申请不等于自动获批。当前资质、结算与费用需确认。 |
| 厦航开放平台 | 接入指南明确个人/企业认证、API 能力申请及测试/生产 IP 白名单。[16] | 航司直连备选；注册个人开发者不等于获全部交易权限，也不能代替全市场比价。 |

【分析】收敛为两条路线：A，天气查询加 Agent 查询/创单、供应商页面付款；B，天气查询加分销 API 完整交易。A 的接入形态更贴合当前个人助理，但必须保留交易状态未知的边界；B 的公开酒店链路更完整，商务和运营成本未知。若 A 无法获得可用权限或订单核对方式，就降为查询跳转，或转 B；不能以演示响应代替验收。

## 5. 决策建议与关键验证

【分析】优先顺序为：和风天气保持；机票先验证途牛；酒店先核实途牛单品契约，同时保留艺龙完整交易候选；只需筛选并由用户自行下单时，选飞猪查询跳转。需要自动同步支付后状态与退改时，优先评估去哪儿机票、艺龙/美团酒店。

| 决策缺口 | 最小验证与判断条件 | 执行状态 |
| --- | --- | --- |
| 当前主体能否用 | 普通账号核查 OAuth/Key、实际可用工具、额度、费用与适用场景；拿不到权限就换路 | 未申请、未执行 |
| 查询是否适合大陆出行 | 在目标部署环境对代表航线/城市和未来日期，只读比较返回价格、税费、退改及页面价格；确认无海外地理编码依赖 | 未执行；地点/日期由实际使用场景确定 |
| 途牛酒店是否满足 | 获取实时 schema，核实详情报价标识、创单结果、支付入口、订单查询、取消与退款方式 | 文档部分不可抓取，待授权后核实 |
| 订单能否核对 | 使用供应商允许的测试环境验证创单、待支付、取消、超时核单；不能确定结果时不自动重试 | 未执行；不以真实付款探测权限 |
| 最终是否形成闭环 | API 回执与供应商页面一致；用户能付款或明确退出；无法同步支付后状态时清晰转供应商页面核对 | 建议验收条件，不声称已达成 |

商务确认应集中在主体资格、最低量/押金/计费、结算方式、展示/缓存、测试环境、售后责任和订单核对能力。这些答案会改变选型，宜先于大规模适配开发获得。

## 6. 阶段目标与演进建议

1. **受限场景可用**：用户能查大陆预警、筛选机酒，查看真实价格和规则；支持已验证的创单服务，经本人确认后创建待支付订单并跳转供应商，或明确由用户在供应商页面完成下单；退出/取消和异常核单有可操作入口。若支付后状态仅可在供应商页面查看，应如实展示；不能宣称五个原工具均已完成全自动替换。
2. **完整交易与稳定运行**：在供应商授权支持下增加支付后订单状态、出票/酒店确认、取消退款和核单；比较阶段 1 的价格变化、超时未知、状态不同步和人工介入情况，制定符合实际使用量的指标。升级供应商应以这些缺口能否消除为依据。

阶段 1 不以工具注册或一次搜索成功验收；阶段 2 也不因供应商宣称有 API 就视为完成。本次调研不包含实施、注册、商务联系或交易授权。
